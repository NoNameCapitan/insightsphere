# ВЛК Offline / Standby — локальна версія 1.0

Робочий допоміжний застосунок для реєстратора, восьми спеціальностей лікарів,
секретаря, голови та заступника голови ВЛК. Реєстрація, чернетки й підтверджені
огляди, підсумок комісії, друк, буфер перенесення в Helsi, JSON / CSV / XLSX
та зашифровані резервні копії працюють на локальному сервері з SQLite.

**Інтернет потрібен рівно один раз — під час встановлення.** Далі
застосунок працює на комп'ютері установи без мережі необмежено довго:
міграції, запуск, огляди, друк, експорт і резервні копії виконуються локально.
Для комп'ютера, який ніколи не матиме інтернету, є портативний пакет
(`npm run pack:offline`). Докладно — `docs/OFFLINE.md`.

Комп'ютер-сервер має бути увімкнений; інші кабінети працюють через локальну мережу.
При втраті зв'язку саме з локальним сервером нові записи зберегти неможливо:
текст відкритої форми залишається на екрані, його можна повторно надіслати,
а внизу екрана з'являється попередження. Не закривайте незбережену форму.
**Медичні дані в браузері не зберігаються.** Service worker кешує лише
незмінні файли інтерфейсу та сторінку-підказку `/offline`; сторінки, потоки
даних і `/api` не кешуються ніколи.

## Найпростіший запуск на Windows

1. Встановіть **Node.js 24 LTS** з офіційного сайту <https://nodejs.org/en/download>.
2. Повністю розпакуйте архів, наприклад у `C:\VLK\vlk-offline-app`.
   Не запускайте файл безпосередньо всередині ZIP.
3. Двічі натисніть **START-WINDOWS.cmd**.
4. Перший запуск завантажить залежності, створить базу, попросить логін,
   ПІБ і пароль першого адміністратора, а потім збере застосунок.
   **Тільки цьому запуску потрібен інтернет** — і кілька хвилин. Пароль має
   містити щонайменше 12 символів; під час введення він не відображається.
   Стандартного пароля немає. Після завершення мережу можна вимкнути.
5. Відкрийте **http://localhost:3000** та увійдіть створеним обліковим записом.
6. У «Працівники й доступ» створіть персональні облікові записи реєстратора,
   лікарів, секретаря та голови. Лікарю обов'язково призначте спеціальність.
7. Залишайте вікно запуску відкритим. Наступного разу запускайте той самий
   файл: він одразу підніме сервер без мережі (готовність — близько секунди).
8. Перевірити автономність у будь-який момент: `npm run offline:check`.

Це пакет із вихідним кодом і автоматизованим локальним запуском, а не
Windows `.exe`. Перевірений запуск виконано на Linux / Node.js 24;
окремий запуск на Windows та Docker у середовищі перевірки не виконувався.
Якщо npm повідомляє про неможливість встановити `better-sqlite3`, перевірте,
що використовуєте підтримувану 64-бітну Node.js 24. Для платформи без готового
бінарного модуля потрібні Python 3 і засоби компіляції C++ або Docker.

## Запуск через термінал — Windows, macOS, Linux

У корені розпакованого проєкту:

```sh
npm run prepare:offline   # єдиний крок, якому потрібен інтернет
npm run offline:check     # перевірка готовності до роботи без мережі
npm start                 # щоденний запуск, мережа не потрібна
```

`prepare:offline` виконує `npm ci`, генерацію клієнта Prisma, міграції,
створення першого адміністратора, імпорт довідника та production-збірку,
а потім записує позначку `.offline-ready.json`. Окремі кроки, як раніше,
теж доступні: `npm ci`, `npm run setup`, `npm run build`, `npm start`.

На Linux/macOS також можна виконати `bash start-local.sh`. Для зупинки —
`Ctrl+C`. Для наступного запуску достатньо `npm start`.
Після зміни вихідного коду штатний запуск сам помітить розбіжність і
перезбере застосунок локально, без мережі.
Для розробки є `npm run dev`; для роботи установи використовуйте production-збірку.

`setup` створює `.env` із абсолютним шляхом до `data/vlk.sqlite`, застосовує
міграції, створює першого адміністратора та імпортує допоміжний каталог.
Усі подальші запуски використовують ту саму базу. Якщо переносите папку на
інший комп'ютер, змініть абсолютний `DATABASE_URL` у `.env`.

## Автономність і портативний пакет

```sh
npm run offline:check             # що готове, а що ні, з командою для виправлення
npm run offline:check -- --serve  # додатково підніме сервер і зробить локальний запит
npm run pack:offline              # архів для комп'ютера, який ніколи не матиме мережі
```

`pack:offline` збирає в `dist-offline/` самодостатній архів з уже
встановленими залежностями та готовою збіркою, файл `.sha256` і коротку
інструкцію. Архів **не містить** `data/`, `backups/`, `.env`, паролів і
медичних даних. Пакет прив'язаний до ОС, розрядності та основної версії
Node.js — для іншої платформи підготуйте окремий.

Повний опис життєвого циклу без мережі — `docs/OFFLINE.md`.
Порівняння зі світовими аналогами та обґрунтування архітектури —
`docs/WORLD-ANALOGUES.md`.

## Встановлення як окреме вікно

На `http://localhost` або локальному HTTPS браузер пропонує встановити
застосунок як окреме вікно (PWA). Це лише спосіб відкриття: дані й далі
залишаються на сервері установи. На звичайному HTTP у локальній мережі
браузер service worker не активує — застосунок працює як звичайна сторінка.

## Щоденний порядок роботи

1. **Реєстратор:** «Новий прийом» → пошук наявного пацієнта або особові дані
   → направлення → маршрут спеціалістів → «Зареєструвати пацієнта».
   Після збереження доступний друк талона. Без РНОКПП потрібно зазначити причину.
2. **Лікар:** відкрити пацієнта зі своєї черги → скарги, анамнез,
   об'єктивні дані → код і формулювання діагнозу → стаття 402 та висновок.
   Можна зберігати чернетку, додавати супутні діагнози, а потім підтвердити огляд.
3. **Секретар:** переглянути зведення оглядів і підготувати повний текст
   підсумкового діагнозу та постанови. Основні діагнози підставляються у проєкт.
4. **Голова / заступник:** перевірити проєкт і підтвердити підсумок після
   завершення всіх потрібних оглядів. Програма не приймає медичного рішення.
5. **Оператор після відновлення Helsi:** «Перенесення» → потрібна картка.
   Кожне поле має кнопку «Копіювати». Вставте у відповідне поле Helsi,
   перевірте збереження та позначте «Внесено й звірено в Helsi».
   Можна копіювати весь огляд блоком, якщо відповідне поле МІС це допускає.
   Частковий прогрес і примітка оператора зберігаються.
6. **Завершення дня:** за потреби «Експорт за день» → JSON, CSV або XLSX;
   зробіть резервну копію бази. Експорт не замінює резервну копію.

**Helsi:** повторне друкування тексту не потрібне, але вставлення у відповідні
поля, вибір записів довідника та підтвердження в МІС виконує оператор.
Це не API-інтеграція з Helsi / ЕСОЗ, не автоматична синхронізація і не
підтверджений формат автоматичного імпорту. Кнопка копіювання сама по собі
не означає, що дані вже внесено в МІС. Якщо під назвою Healthy мається на увазі
інший продукт, буфер звичайного тексту працюватиме аналогічно, але відповідність
полів потрібно звірити в його інтерфейсі.

## Ролі та права

| Роль               | Доступ                                                                                               |
| ------------------ | ---------------------------------------------------------------------------------------------------- |
| Адміністратор      | Облікові записи, ролі, спеціальності; самостійно клінічні картки не відкриває                        |
| Реєстратор         | Особові дані, направлення, маршрути, стан оглядів, талон; без текстів оглядів та клінічного експорту |
| Лікар              | Пацієнти свого маршруту, власна спеціальність, чернетка / підтвердження / нова версія огляду         |
| Секретар           | Усі огляди, проєкт підсумку, перенесення, друк зведення, експорт                                     |
| Голова / заступник | Повноваження секретаря та підтвердження підсумку                                                     |

Одній людині можна надати кілька ролей, наприклад «Лікар — стоматолог»
і «Заступник голови». Зміна доступу або пароля відкликає активні входи
цього працівника. Обліковий запис можна вимкнути, не видаляючи історію оглядів.
Вхід діє до 8 годин, за бездіяльності — до 60 хвилин. Якщо він сплив під час
роботи з формою, увійдіть у новій вкладці, поверніться до форми та збережіть її.

## Виправлення та одночасна робота

Чернетку редагує лікар, який її створив. Після підтвердження використовуйте
«Створити виправлення» і зазначте причину: попередня версія зберігається.
Закриту сесію секретар або голова виправляє через нову пов'язану сесію;
лікарські поля підставляються з попередньої, але потребують нового підтвердження.
Старий документ залишається в історії та перестає бути доступним для перенесення.

Якщо інший працівник змінив картку, збереження повідомить про конфлікт.
Натисніть «Оновити стан» і повторіть збереження. Зміни одного лікаря не
перезаписують підтверджені записи іншого. Для однакової чернетки в двох вкладках
звірте обидва варіанти перед оновленням; попередньо скопіюйте незбережений текст.

## Локальна мережа установи

Одна SQLite зберігається на диску одного сервера. **Не розміщуйте SQLite-файл
на спільному SMB/NFS-диску і не запускайте кілька копій серверів над одним файлом.**
Комп'ютери кабінетів відкривають вебадресу сервера.

Приклад для IP сервера `192.168.1.10`: змініть `.env`:

```dotenv
APP_ORIGIN="http://192.168.1.10:3000"
ALLOWED_ORIGINS="http://192.168.1.10:3000,http://localhost:3000,http://127.0.0.1:3000"
```

Потім виконайте `npm run start:lan`. Дозвольте вхідний порт 3000 у брандмауері
тільки з адрес установи. Не налаштовуйте публічну переадресацію порту.
Для передавання медичних даних між кабінетами налаштуйте локальний HTTPS
через reverse proxy з довіреним на робочих місцях сертифікатом:
тоді `APP_ORIGIN` і `ALLOWED_ORIGINS` мають містити точну HTTPS-адресу,
а `COOKIE_SECURE=true`. Зовнішній CDN або хмарний proxy не потрібний.

На HTTP у LAN браузер може не підтримувати сучасний Clipboard API.
Програма використовує резервне копіювання виділеного тексту; якщо браузер
відмовить і в ньому, поле буде виділене з підказкою натиснути Ctrl+C.

У коді немає зовнішніх шрифтів, трекерів, аналітики або API-запитів із картками.
SQLite сама по собі не зашифрована: захистіть обліковий запис ОС і використайте
шифрування диска. Буфер обміну й завантажені файли містять медичні дані;
вимкніть хмарну синхронізацію буфера та працюйте в локальному профілі браузера.

## Docker Compose

Перший раз потрібні Docker Compose та інтернет для збірки образу:

```sh
docker compose build
docker compose run --rm app npm run setup
docker compose up -d
```

Відкрийте `http://localhost:3000`. За замовчуванням порт доступний лише локально.
У Compose база і резервні копії зберігаються в окремих постійних volumes.
Мережа контейнера `internal: true` не дає йому виходу в інтернет під час роботи.
Для доступу з LAN задайте у `.env` `BIND_ADDRESS=0.0.0.0`, правильні
`APP_ORIGIN` / `ALLOWED_ORIGINS` і обмеження брандмауера.

```sh
docker compose logs --tail=100 app
docker compose stop
docker compose start
```

Не використовуйте `docker compose down -v`: `-v` видаляє volumes з даними.
Для перенесення вже зібраного образу на офлайн-сервер:

```sh
docker save -o vlk-offline-image.tar vlk-offline-standby:1.0
# На цільовому сервері, разом із compose.yaml:
docker load -i vlk-offline-image.tar
docker compose run --rm --no-deps app npm run setup
docker compose up -d --no-build
```

Після завантаження образу мережеве завантаження npm-пакетів не потрібне.
Файл образу не входить у ZIP. Docker-конфігурація підготовлена, але контейнерний
запуск не перевірений тут через відсутність Docker Engine.

## Резервне копіювання і відновлення

```sh
npm run backup
```

Задайте окремий надійний пароль. Копія `backups/*.vlkbak` шифрується
AES-256-GCM; її можна створювати під час роботи сервера, включно з даними WAL.
Зберігайте копію на окремому захищеному носії, пароль — окремо від копії.
Втрата пароля не дозволить її відновити.

```sh
npm run restore -- /повний/шлях/до/копії.vlkbak
```

Відновлення створює **новий** `data/restored-....sqlite` і перевіряє цілісність.
Робочу базу не перезаписує. Зупиніть сервер, змініть `DATABASE_URL` у `.env`
на надрукований шлях і запустіть знову. Усі працівники входять повторно.
Поточну базу збережіть до перевірки відновленої.

Для Docker: `docker compose exec app npm run backup`, а щоб вивантажити
копії — `docker compose cp app:/app/backups ./docker-backups`.
Відновлений контейнерною командою файл лежить у volume `/app/data`;
для перемикання змініть `DATABASE_URL` у секції `environment` файлу Compose
і виконайте `docker compose up -d`. Докладніше — `docs/OPERATIONS.md`.

## Довідник МКХ та документи

Пакет містить **9530 кодів історичного відкритого довідника eHealth від
04.06.2019** з походженням у `reference-data/PROVENANCE.md`.
Це допоміжний пошук, а не підтвердження актуальності НК 025:2021 або
сьогоднішнього довідника Helsi. Код, формулювання діагнозу і статтю перевіряє лікар.
Можливе ручне введення коду з документа; воно позначається окремою версією.

Актуальний дозволений для використання закладом каталог імпортується локально:

```sh
npm run import:icd -- /повний/шлях/до/icd10.json
```

Структура JSON:

```json
{
  "version": "ідентифікатор-версії-установи",
  "source": "джерело або номер документа установи",
  "entries": [
    { "code": "Z00.0", "title": "Назва відповідно до вашого каталогу" }
  ]
}
```

Ідентифікатор версії не можна повторно використовувати для іншого змісту.
Попередні версії лишаються для історичних записів. У результатах пошуку
показано версію довідника, з якої вибраний код.

Друкуються талон і **робоче зведення ВЛК** через браузер, у тому числі в PDF.
Зведення не є затвердженим бланком форми № 122/о, довідки ВЛК або свідоцтва
про хворобу. Нормативна відповідність шаблону наказу № 402 не заявляється;
для офіційного документа використовуйте затверджену установою форму / МІС.
Підтвердження в застосунку не є КЕП. Статті й повний текст постанови
вводить уповноважений працівник за чинною редакцією.

## Технічна основа й перевірки

Next.js 16 / App Router / Server Actions, TypeScript, Tailwind 4,
локальні компоненти shadcn/ui на Radix, Lucide, Prisma 7 / SQLite.
Усі основні версії залежностей і `package-lock.json` зафіксовані.

```sh
npm run db:validate
npm run typecheck
npm test
npm run build
npm run offline:check -- --serve
```

`npm test` створює окрему тимчасову БД та перевіряє реальні міграції,
транзакції, права, версії, незмінність, перенесення і резервні копії, а також
автономність: сумісність локального рушія міграцій із форматом Prisma,
відсутність зовнішніх адрес у коді інтерфейсу та те, що service worker не
кешує медичні дані.
Результати браузерної перевірки та межі перевіреного — `docs/VALIDATION.md`.
Структура проєкту — `docs/PROJECT-STRUCTURE.md`.

Посилання Vercel із попереднього етапу не запускає цей локальний сервер.
Розгортайте цю версію на комп'ютері установи з постійним диском.
