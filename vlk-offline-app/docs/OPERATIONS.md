# Експлуатація

## Перший адміністратор

`npm run setup` запитує дані тільки тоді, коли таблиця User порожня.
Для автоматизованої інсталяції допустимі змінні BOOTSTRAP_ADMIN_USERNAME,
BOOTSTRAP_ADMIN_NAME, BOOTSTRAP_ADMIN_PASSWORD. Передавайте пароль через
захищений механізм оточення; не записуйте його у вихідний код або загальні скрипти.
Після створення адміністратора ці змінні більше не потрібні.

## Конфігурація

- DATABASE_URL: `file:` та абсолютний локальний шлях до SQLite.
  Значення `libsql://…` вмикає хмарний режим (див. `docs/VERCEL.md`);
  у ньому потрібен також DATABASE_AUTH_TOKEN, а автономність не діє.
- APP_ORIGIN: адреса, яку вводять у браузері.
- ALLOWED_ORIGINS: дозволені точні адреси через кому, без завершального `/`.
- COMMISSION_NAME: назва комісії за замовчуванням у новому прийомі.
- ORDER_402_REVISION: реквізити редакції, яку використовує установа.
- COOKIE_SECURE=true: лише для HTTPS; на звичайному HTTP не встановлюйте.
- PORT: порт Node-сервера, за замовчуванням 3000. При зміні оновіть origins.
- NEXT_TELEMETRY_DISABLED=1: встановлено також усіма штатними скриптами запуску.
- CHECKPOINT_DISABLE=1, DO_NOT_TRACK=1, PRISMA_HIDE_UPDATE_MESSAGE=1:
  вимикають перевірки версій, які в офлайні чекали б на таймаут DNS.
  Штатні скрипти встановлюють їх самостійно.

Зміна .env потребує перезапуску. Зміна коду або конфігурації Next.js — нової збірки.
DATABASE_URL не повинен посилатися на мережевий файловий ресурс.
Резервна копія й відновлення приймають BACKUP_PASSWORD для автоматизації;
інтерактивний запуск запитує його приховано.

## Відновлення в Docker

1. Скопіюйте зашифровану копію в контейнер:
   `docker compose cp ./copy.vlkbak app:/app/backups/copy.vlkbak`.
2. Виконайте `docker compose exec app npm run restore -- /app/backups/copy.vlkbak`.
3. Запишіть надрукований шлях `/app/data/restored-....sqlite`.
4. Зупиніть застосунок: `docker compose stop app`.
5. У compose.yaml змініть DATABASE_URL на `file:/app/data/restored-....sqlite`.
6. `docker compose up -d` застосує конфігурацію; перевірте входи та записи.

Відновлення не змінює старий файл. Не вилучайте стару базу, поки не перевірили
нову. Відкликання входів у відновленій копії навмисне.

## Що входить у копію

Усі SQLite-таблиці: користувачі та хеші паролів, пацієнти, сесії, огляди,
діагнози, словники, документи, журнал перенесення й аудит. Конфігурація .env,
пароль резервної копії та вихідний код до копії не входять. Зберігайте версію
пакета, з якою зроблено копію; перед оновленням створюйте нову копію.

## Якщо щось не працює

- Сторінка недоступна: перевірте вікно серверного запуску, адресу і порт.
- Не вдається увійти: перевірте розкладку, активність облікового запису та
  origins. П'ять невдалих спроб одного логіна дають паузу на 15 хвилин.
- «Адреса доступу не дозволена»: додайте точну адресу браузера до ALLOWED_ORIGINS.
- HTTP з COOKIE_SECURE=true: cookie не збережеться; виправте конфігурацію.
- «Картку вже змінив інший працівник»: звірте стан і збережіть знову.
- «Дані форми залишилися»: не закривайте вкладку; відновіть локальний сервер
  або вхід і повторіть дію.
- Не копіюється: текст буде виділений; Ctrl+C / ⌘C або системне «Копіювати».
- Код не знайдено: перевірте версію довідника; лікар може ввести код з документа.
- Порт зайнятий: закрийте інший екземпляр або змініть PORT та origins.
- Запуск просить інтернет удруге: змінився `package-lock.json` або зникла
  папка `node_modules`. Діагностика: `npm run offline:check`.
- Помилка двійкового модуля після перенесення пакета: пакет зібрано для іншої
  ОС, розрядності або основної версії Node.js. Потрібен окремий
  `npm run pack:offline` на відповідній платформі.
- «Контрольна сума міграції не збігається»: файли `prisma/migrations` змінювати
  не можна. Поверніть початкові файли пакета або відновіть базу з копії.
- Банер «Локальний сервер не відповідає»: перевірте вікно запуску на сервері,
  живлення й мережу кабінету. Незбережений текст залишається на екрані.
- Застарілий інтерфейс після оновлення: закрийте всі вкладки застосунку й
  відкрийте знову — кеш оболонки прив'язаний до ідентифікатора збірки.

Експорт за день обмежений 2000 сесіями; при перевищенні виводиться помилка,
замість неповного файлу. Черга показує до 300 збігів на запит із явним лічильником;
використовуйте пошук за прізвищем, РНОКПП чи талоном.

## Відповідність і захист

Усі клінічні рішення залишаються за лікарями та комісією. Коди, статті,
формулювання та офіційні бланки не перевіряються автоматично на нормативну
відповідність. Немає сертифікації МІС / підключення до центральної бази ЕСОЗ.

Робоча БД захищена ролями на сервері, але адміністратор ОС із доступом до
файлів може прочитати SQLite. Застосуйте шифрування диска, індивідуальний
доступ до ОС, локальний HTTPS, резервний носій та UPS відповідно до умов установи.
Не виводьте порт у публічний інтернет. Друк і ручне перенесення у вибрану МІС
є усвідомленими діями працівника; застосунок сам картки назовні не надсилає.
