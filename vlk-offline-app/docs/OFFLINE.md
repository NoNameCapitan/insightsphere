# Робота без інтернету

Застосунок розрахований на **один запуск з мережею і подальшу роботу без неї**.
Інтернет потрібен рівно один раз — щоб завантажити залежності та зібрати
застосунок. Після цього жоден штатний крок не звертається до мережі.

## Що саме потребує мережі

| Крок                            | Мережа   | Коли виконується         |
| ------------------------------- | -------- | ------------------------ |
| `npm ci` — завантаження пакетів | потрібна | один раз                 |
| `prisma generate`               | ні       | під час підготовки       |
| Міграції бази                   | ні       | автоматично при запуску  |
| Production-збірка Next.js       | ні       | під час підготовки       |
| Створення адміністратора        | ні       | один раз                 |
| Імпорт довідника МКХ            | ні       | один раз, локальний файл |
| Щоденний запуск сервера         | ні       | щоразу                   |
| Робота кабінетів, друк, експорт | ні       | щоразу                   |
| Резервні копії та відновлення   | ні       | за розкладом установи    |

Телеметрія Next.js, перевірка версій Prisma (`CHECKPOINT_DISABLE`) і сповіщення
npm вимкнені в усіх штатних скриптах. Інакше кожен офлайн-старт чекав би на
таймаут DNS. Міграції застосовує власний локальний рушій
(`scripts/migrate-offline.mjs`), тому Prisma CLI під час запуску не потрібен.

## Сценарій 1. Комп'ютер, який один раз має інтернет

```sh
npm run prepare:offline     # єдиний крок, якому потрібна мережа
npm run offline:check       # перевірка готовності
npm start                   # щоденний запуск, мережа не потрібна
```

Windows: двічі натисніть **START-WINDOWS.cmd**. Перший запуск сам виконає
підготовку, наступні одразу піднімуть сервер. Після підготовки мережу можна
вимкнути назавжди.

`prepare:offline` створює файл `.offline-ready.json` — позначку з версією
Node.js, платформою, контрольною сумою `package-lock.json` і відбитком
вихідного коду. За нею `npm start` розрізняє перший і звичайний запуск.

## Сценарій 2. Комп'ютер, який ніколи не матиме інтернету

Підготуйте пакет на іншій машині **з такою самою ОС, розрядністю і версією
Node.js** — у пакеті є двійкові модулі:

```sh
npm run prepare:offline
npm run pack:offline
```

У `dist-offline/` з'явиться архів, файл `.sha256` і коротка інструкція.
Архів містить уже встановлені залежності та готову збірку, але **не містить**
`data/`, `backups/`, `.env`, паролів і жодних медичних даних.

На цільовому комп'ютері:

1. Встановіть Node.js тієї ж основної версії (інсталятор перенесіть тим самим носієм).
2. Розпакуйте архів.
3. Звірте контрольну суму архіву з файлом `.sha256`.
4. Запустіть `START-WINDOWS.cmd` або `bash start-local.sh`.
5. Програма створить `.env`, базу й запитає першого адміністратора — без мережі.

Для іншої ОС або іншої основної версії Node.js потрібен окремий пакет:
`npm run offline:check` зупинить запуск із відповідним поясненням, а не
покаже незрозумілу помилку двійкового модуля.

## Перевірка автономності

```sh
npm run offline:check            # стан готовності
npm run offline:check -- --serve # додатково підніме сервер і зробить запит
```

Перевіряються версія Node.js, наявність залежностей і двійкового модуля SQLite,
згенерований клієнт Prisma, готова збірка, відповідність збірки вихідному коду,
`.env`, база даних, відповідність платформи, а також реальне читання таблиць.
Кожен незакритий пункт супроводжується командою для виправлення.

Наявність мережі показується довідково: для роботи вона не потрібна.

## Оновлення застосунку

Після зміни вихідного коду `npm start` сам помітить розбіжність відбитка і
перезбере застосунок **локально** — мережа для цього не потрібна.
Нові пакети (зміна `package-lock.json`) потребують `npm run prepare:offline`
з інтернетом або нового портативного пакета.

Перед оновленням зробіть резервну копію: `npm run backup`.

## Браузер

Сторінки, потоки даних і `/api` **ніколи не зберігаються в браузері**:
медичні записи залишаються на сервері установи. Service worker кешує лише
незмінні файли інтерфейсу (`/_next/static`), значки, маніфест і статичну
сторінку `/offline` з поясненням, що робити при втраті зв'язку.
Версія кешу прив'язана до ідентифікатора збірки, тому після оновлення
застарілі файли видаляються.

Застосунок можна встановити як окреме вікно (PWA) — це не змінює місця
зберігання даних. Service worker реєструється лише в захищеному контексті:
`http://localhost` або локальний HTTPS. На звичайному HTTP у LAN браузер його
не активує, і застосунок працює як звичайна вебсторінка.

У нижній частині екрана з'являється попередження, якщо щось заважає
зберегти запис. Воно розрізняє два різні випадки:

- **сервер не відповідає** — втрачено зв'язок із комп'ютером-сервером;
- **база даних недоступна** — сервер працює, але сховище не готове.

Незбережений текст форми залишається на екрані — не закривайте вкладку,
усуньте причину й повторіть збереження. Коли сторінка вже показує екран
очікування, банер не дублюється.

## Часті питання

- **Чи можна взагалі не вмикати мережу на цьому комп'ютері?**
  Так — за сценарієм 2 з портативним пакетом.
- **Чи піде щось «наверх» під час роботи?**
  Ні. У коді немає зовнішніх шрифтів, аналітики та API-запитів;
  це перевіряє автоматичний тест `npm test`.
- **Чому запуск просить інтернет удруге?**
  Змінився `package-lock.json` або зникла папка `node_modules`.
  Діагностика: `npm run offline:check`.
- **Чи працюватиме пакет з Linux на Windows?**
  Ні. Двійкові модулі збираються під конкретну платформу.
