# v36.1 — виправлення шрифтів і перевірка чистої збірки

Дата роботи: 29.09.2026. Основа: v36 home-motion.

## Що виправлено

На скриншоті помилка Vercel завершує `npm run build:next`, а стек містить
модуль `next/font/google`. Повний первинний текст помилки на скриншоті обрізаний.
У попередній версії три гарнітури потребували завантаження Google Fonts
під час чистої збірки. Цю зовнішню залежність усунуто.

IBM Plex Sans, IBM Plex Mono та PT Serif тепер включені в `app/fonts/`
та підключені через `next/font/local`. Оригінальні TTF завантажені з
репозиторію google/fonts; файли не модифіковані. Додані ліцензії,
джерела та SHA-256. Наявні ваги, курсив і всі українські літери збережено.

Маніфест та service worker включають TTF-ресурси. Під час браузерної QA
виявлено наявну проблему: валідатор відхиляв коректні імена Turbopack
на кшталт `valid-hash..js`. Тепер забороняються сегменти `..`/`.` та
закодовані/зворотні розділювачі, а не дві крапки всередині імені файла.
Додані тести офлайн-видачі TTF і перевірки безпечних/небезпечних шляхів.

перед вибором статті; це виправлення QA-сценарію, не зміна інтерфейсу.

## Межі та незмінне

Vercel deployment у вашому акаунті не запускався. Точну мережеву причину
помилки віддаленого builder не можна встановити з обрізаного скриншота;
цей випуск усуває виявлену залежність шрифтів і проходить чисту збірку локально.
Фізичні iOS/Safari та оновлення service worker зі старої production-версії
не перевірені. Перевірено свіжу офлайн-інсталяцію у Chromium.

Без змін: app/page.tsx, app/globals.css, усі components/, lib/, нормативні
дані, пошук, сесія, UI та анімації v36. Lockfile і залежності збережено.
Змінені тільки layout/шрифти, офлайн-маніфест, його service worker, відповідні
регресійні тести й документація. Перевірки не вимикалися і не послаблювалися.

## Як передеплоїти

1. Розпакуйте ZIP і замініть вихідні файли репозиторію, включно з `app/fonts/`.
2. Створіть новий deployment цієї версії. Root Directory — каталог із package.json.
3. Install Command: `npm ci`. Build Command: `npm run build:next`.

Перезапуск старого deployment без заміни коду не застосує виправлення.
Не треба вимикати TypeScript/ESLint чи змінювати Framework Preset.
Архів не містить node_modules, .next, .vinext, dist, кешів, локальних .env і секретів.
