# v38.3 — безперервний робочий сценарій лікаря

Дата перевірки: 01.10.2026. Єдина вихідна версія — наданий користувачем
`VLK-Navigator-402-v38.2-sidebar-reading-space.zip`.

## Що стало зручніше

1. **Повернення до списку без втрати роботи.** Натискання «Результати пошуку»
   над статтею повертає до того самого списку, зберігаючи запит, фільтри,
   статтю та вибраний пункт. Клавіатурний фокус переходить на вибраний рядок.
   Перехід на головну лишається окремою дією у шапці.
2. **Стабільна спеціальність.** Пошук, недавні перегляди й швидкий доступ
   зберігають спеціальність лікаря, якщо стаття до неї належить. Наприклад,
   відкриття статті 38 у хірурга більше не перемикає його на терапевта.
   Явно задана область пошуку має пріоритет; несумісний контекст безпечно
   замінюється спеціальністю самої статті.
3. **Видима область пошуку.** Активне обмеження спеціальністю видно й після
   закриття пошукової панелі. Повернення до всіх спеціальностей — одна дія.
4. **ТДВ без зайвих колонок.** Якщо призначення обрано, спочатку видно його
   графу. Усі рядки загальних вимог і всі 75 рядків статей збережено.
   Кнопка «Усі 12 граф» відкриває повну таблицю; перемикання не змінює
   параметрів огляду. Повна назва призначення доступна у підписаному
   розкривному блоці. У повному вигляді вибрана графа прокручується у видиму
   область з урахуванням закріпленого першого стовпця.
5. **Передбачувані «Назад / Вперед».** У межах відкритої сторінки відновлюються
   запит, спеціальність, стаття, пункт, фільтри й активна панель. Маркер історії
   містить лише службовий ідентифікатор, без запиту чи медичних даних.
   Після завершення сесії попередній стан не відновлюється; старі маркери
   іншої сесії або сторінки відхиляються.

Візуальні зміни локальні: компактний перемикач ТДВ, явне повернення до списку,
активна область пошуку. Використано наявні кольорові токени обох тем, видимі
focus-стани й 44px кнопки основних нових дій. Емблеми, анімації й шрифти не змінені.

## Межі перевірки

DOM-сценарій реально монтував React-застосунок у jsdom і перевіряв збереження
спеціальності, запиту та пункту, фокус рядка, Back/Forward, кількість стовпців
і рядків ТДВ, незмінність призначення та повторне відкриття. Компонент
Next Image замінено тестовим img; медична логіка й обробники не підмінялися.
jsdom не виконує браузерного компонування та не перевіряє пікселі чи геометрію.


- **Браузер, піксельний вигляд, реальні мобільні прокручування, фокус та
  теми — BLOCKED / NOT RUN.** Cloud browser повернув `net::ERR_BLOCKED_BY_CLIENT`
  для `localhost:3000`, `127.0.0.1:3000` і передбаченого локального
  `terminal.local:3000`. Обмеження не обходилося. Зображень «до / після» немає.
- Запуск vinext dev у цьому середовищі завершився системною помилкою
  `uv_interface_addresses`. Next dev стартував; обидві production-збірки
  завершилися успішно. Це окремо від браузерного блокування.
- Реальний офлайн smoke-test, Safari та фізичні пристрої — NOT RUN.
  Модульні PWA-перевірки входять до 185 тестів; service worker не змінено.
- Чинність нормативної редакції на 01.10.2026 заново не перевірялася.
  Дати, медичні висновки й офіційні тексти залишені як у наданому v38.2.
- Деплой, push, merge, нова авторизація чи зовнішній моніторинг не виконувалися.

## Запуск і наступна перевірка

Node.js >=22.13.0. `npm ci` → `npm run build:next` → `npm run start:next`.
Альтернативний production-шлях: `npm run build`.

Перед публікацією потрібен браузерний прогін на 390×844, 1024×768 і 1366×768:
хірург → «38б» → результат → назад до списку → читання → Back/Forward;
ТДВ 9 → усі графи → закрити / повторно відкрити; обидві теми, клавіатура,
порожні результати, завершення сесії та офлайн-перезавантаження.
Це перевірена кодова ітерація, а не твердження про завершену візуальну валідацію.
