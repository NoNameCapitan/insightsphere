# VLK Навігатор — правила роботи з репозиторієм

## Мета продукту

- Розвивати компактний браузерний навігатор по Наказу МОУ №402 для лікарів ВЛК, військових юристів і військовозобов’язаних.
- Пріоритет: точна нормативна навігація, швидкий пошук, зрозуміле зіставлення підтвердженого стану з пунктом і локальне зведення.
- Принцип UX: **less clicks, more context**. Не перетворювати робочий dashboard на довгий маркетинговий лендинг.
- Результат аналізатора — лише попередній нормативний орієнтир, а не діагноз чи постанова ВЛК.

## Джерело правди та захищений нормативний шар

- Репозиторій відтворює нормативні дані редакції Наказу №402 від `22.08.2025`. Ця дата описує представлену редакцію, а не автоматично підтверджує актуальність на сьогодні.
- Перед твердженням про чинність або нову редакцію перевіряти офіційне джерело: `https://zakon.rada.gov.ua/laws/show/z1109-08#Text`.
- Не скорочувати, не перефразовувати й не «покращувати» дослівні нормативні формулювання.
- Не замінювати точні коди МКХ широкими діапазонами, не вигадувати діагнози, критерії, відповідності, висновки або відсутні пояснення.
- Чітко відділяти в UI: офіційний дослівний текст, короткий навігаційний опис і попередній орієнтир.
- Не змінювати нормативні дані заради косметичного рефакторингу.

Критичні файли:

- `lib/vlk-official-articles.ts` — МКХ і дослівна третя графа для 87 статей;
- `lib/vlk-rules.ts` — пункти й дослівні результати;
- `lib/explanations/` та `lib/vlk-explanations.ts` — офіційні пояснення, метадані й контрольна сума;
- `lib/vlk-anchors.ts` і `lib/vlk-links.ts` — офіційні переходи та підсвічування;
- `lib/vlk-tdv.ts` і `lib/vlk-tdv-general.ts` — ТДВ;
- `lib/vlk-sample-data.ts` — навігаційні назви, спеціальності й короткі описи;
- `tests/vlk-data.test.mjs` — інваріанти нормативної бази.

Якщо офіційне джерело суперечить коду, спочатку зафіксувати точну розбіжність. Вносити мінімальне виправлення разом із відповідними тестами, метаданими редакції та контрольними сумами.

## Архітектура та незмінні обмеження

- Зберігати поточний стек: Next.js 16, React 19, TypeScript, Tailwind, vinext/Cloudflare Workers і npm lockfile.
- Основна функціональність і медичні дані залишаються локальними в браузері. Не додавати бекенд, авторизацію, аналітику, трекери або передачу медичних даних без окремого завдання.
- Не видаляти PWA/service worker і не ламати офлайн-роботу після першого завантаження.
- Не змінювати `.openai/hosting.json`, `vercel.json`, build-скрипти або обидва шляхи деплою без прямої потреби завдання.
- Не ламати читання старих записів `localStorage` після зміни схем сесії, історії чи робочого простору.
- Не додавати `any`, не вимикати правила TypeScript/ESLint, не видаляти й не послаблювати тести для приховування помилки.
- Не комітити `.env*`, секрети, `node_modules`, `.next`, `dist`, `.wrangler`, логи, кеші або діагностичні артефакти.

## UX-інваріанти

- На першому екрані зберігати доступними спеціальність, пошук/статтю, МКХ і головну дію.
- Пошук не повинен вигадувати відповідності; точний номер статті та точний код МКХ мають найвищий пріоритет.
- Довгі офіційні тексти не обрізати. Використовувати підписані акордеони, модальні вікна або внутрішній скрол.
- ТДВ відкривати у повноекранному читабельному режимі без горизонтального скролу сторінки.
- Підтримувати мобільний layout, клавіатурну навігацію, видимий focus-state і достатні touch targets.
- Кольори результатів: червоний лише для непридатності/критичних застережень, жовтий для проміжного орієнтира, зелений для придатності.

## Робочий процес

1. Перед змінами прочитати `README.md`, `package.json` і файли, що безпосередньо формують змінюваний сценарій.
2. Зафіксувати вихідний стан і відокремити наявні помилки від нових.
3. Вносити найменшу завершену зміну, яка покращує реальний користувацький сценарій.
4. Після змін переглянути diff і запустити релевантні перевірки.
5. Не заявляти про браузер, деплой, офлайн-режим або інтеграцію, якщо їх фактично не перевірено.

Базова матриця перевірки для змін коду:

```bash
npm ci
npm run lint
node --test tests/vlk-data.test.mjs
npm run build
node --test tests/*.test.mjs
```

Для змін, що впливають на Vercel/Next.js, додатково запускати `npm run build:next`. Використовувати Node.js `>=22.13.0`.

## Готовність і передача результату

- Ключовий сценарій працює end to end у фактично перевіреному середовищі.
- Нормативні інваріанти збережено: 87 статей, 87 записів третьої графи, 29 контрольованих точних наборів МКХ, повнота спеціальностей, пунктів, якорів, пояснень і статус статті 87.
- Результати перевірок звітувати як `PASS`, `FAIL` або `BLOCKED`; окремо називати неперевірені зовнішні кроки.
- Якщо замовлено архів, повертати один чистий ZIP без старих вкладених архівів, секретів, кешів, логів і build-артефактів.
- У фіналі коротко вказати: що змінено, що реально перевірено, обмеження та одну найкращу наступну дію.
