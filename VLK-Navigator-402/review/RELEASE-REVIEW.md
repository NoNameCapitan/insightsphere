# Передача v19 на експертну і польову перевірку

Дата підготовки: 09.09.2026. Це сценарії майбутнього приймання, не результати
випробувань із лікарями. Не використовуйте персональні дані пацієнтів.

## 1. Медична та юридична звірка — очікує виконання

`articles-review.csv` містить усі 87 статей, профільних лікарів і джерело.
Лікар ВЛК та військово-медичний юрист незалежно фіксують:

- відповідність «Включено», винятків МКХ, кожної умови та результату пункту;
- повноту пояснення, відповідність рядків/колонок/об’єднань 19 таблиць;
- графи ТДВ, примітки, антропометричні критерії (зріст, маса), зв’язок із пунктами;
- коректність переходу до джерела та межі попереднього орієнтира.

Не заповнювати «перевірено» без ПІБ, ролі, дати та переліку звірених норм.
Автоматично знайдено 2570/2570 фрагментів у HTML джерела — це перевірка
наявності тексту, не його положення в таблицях, не повноти всього живого документа
і не правильності постанови. Для статті 87 немає окремого пояснення: це штатно.

Відтворення технічної звірки (Node 22.13+, Python 3, завантажений HTML
офіційної сторінки, не сторінка блокування):

```bash
npm run check:edition
node scripts/audit-source.mjs /path/to/official-402.html
```

Артефакт конкретної звірки: `source-check-2026-09-09.json`.
Джерело: https://zakon.rada.gov.ua/laws/show/z1109-08

## 2. Пристрої — очікує фізичної перевірки

| Середовище | Що перевірити | Результат |
| --- | --- | --- |
| Windows, Edge/Chrome, системний масштаб 125% і 150% | усі спеціальності, низ списку, нерухомий фон меню | Не виконано |
| iPhone, Safari, портрет/альбом | акордеони, клавіатура, ТДВ, закриття діалогу | Не виконано |
| Android, Chrome, портрет/альбом | пошук, вибір пунктів, кошик, великі таблиці | Не виконано |
| Усі три, світла/темна/системна тема | контраст, фокус, межі вікон | Не виконано |

Прийняття: горизонтально не прокручується вся сторінка; широкі таблиці
прокручуються лише всередині блоку; кнопки закриття й усі статті доступні;
меню не зсуває основний екран; пояснення в центрі, ТДВ на весь екран.

## 3. Офлайн та оновлення production-збірки — очікує браузерної перевірки

1. Відкрити preview production-збірки v19 у новому профілі браузера онлайн.
2. Дочекатися «Офлайн-копія готова». Вимкнути мережу.
3. Перезавантажити; відкрити статті 1, 13, 47, 87, пояснення і ТДВ.
4. Зберегти синтетичний пункт; відновити вкладку. Перевірити кошик.
5. В окремому preview відкрити v18, оновити його до v19. Старий огляд не
   повинен перезавантажитися без натискання «Оновити».
6. Симулювати помилку завантаження одного chunk: попередній офлайн-реліз
   має лишитися доступним. Повторити після успішного оновлення.
7. Відкрити дві вкладки v19; завершити синтетичну сесію в одній. В обох
   кошик та історія мають очиститися; тема й офлайн-доступ мають зберегтися.

Вбудовані модульні тести перевіряють ці правила кешу в моделі CacheStorage,
але не замінюють повний браузерний цикл установки й оновлення.

## 4. Коротке тестування з 3–5 лікарями — готовий сценарій

Учаснику дати лише URL, без навчання. Виміряти час, кількість помилкових
кліків, звернень по допомогу та оцінку легкості 1–7 для кожного завдання:

| Завдання | Критерій завершення |
| --- | --- |
| Знайти J45, відкрити пояснення | стаття 47, дослівний текст видимий |
| Знайти «гіпертонія», перемкнути фільтр результату | стаття/пункти релевантні, контекст не зник |
| Психіатр → стаття 14 → пункт | результат відразу читається, кошик доступний |
| Знайти таблицю у статті 13 | таблиця розгортається, рядки/колонки читаються |
| Відкрити ТДВ і знайти зріст/масу | потрібні колонки й примітки знайдені |
| Повернутися до кошика, відкрити додаткове | чернетка прихована до розкриття |
| Завершити синтетичний огляд | користувач сам знаходить очищення та розуміє його наслідки |

Запис для кожного учасника: анонімний ID, спеціальність, пристрій, завдання,
час, помилки, допомога, оцінка, короткий коментар. Не записувати діагнози
реальних людей. Виправляти спочатку повторювані блокери пошуку й читання,
після цього вирішувати, чи варто взагалі повертати PDF до основних дій.
