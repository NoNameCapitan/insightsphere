Відмінність від аналогів: український інтерфейс, пояснювана оцінка ліда, готові звернення UA/RU/EN, локальні дані без сервера. Чого немає: власної бази контактів, верифікації email, автоматичних розсилок.

### Виправлені помилки

- Пошук за містом обрізав результати колом 5 км від центру: у Києві відпадала більша частина міста (демо «стоматології Київ» — 4–5 лідів замість 20). Тепер типово «Усе місто» з радіусом міста; явний радіус працює як раніше.
- Для будь-якого міста, крім Києва, не було координат: відстань, радіус і карта не працювали. Додано 24 міста України з відмінками та латиницею; невідома адреса геокодується одним запитом Places за наявності ключа.
- Google-тип `store` відносив пекарні, аптеки та інші магазини до ніші «Ремонт / сервіс». Прибрано; якщо місце відповідає запитаній ніші, вона має пріоритет (кафе-ресторан у пошуку ресторанів лишається рестораном).
- Остаточно зачинені заклади потрапляли в ліди. Тепер відкидаються.
- Парсер не розпізнавав «з телефоном», «вет клініки», «детейлінг», «відкрито зараз» і міста поза п’ятіркою найбільших.
- У списку вибору кампанії перша кампанія дублювалась.
- Тема листа була українською навіть для RU/EN чернеток; статус бізнесу показувався як `OPERATIONAL`.
- Дошка кампанії не вміщала колонку «Результат» на екрані 1440 px.
- Кнопка карти була вимкнена без ключа Google.
- CI лежав у підпапці і GitHub його не запускав; перенесено в корінь репозиторію.

### Нове

- Контакти з сайту: картка, таблиця, деталі ліда, CSV, показник «Email / соцмережі». Email підставляється в Gmail/Outlook/mailto; кнопки Telegram, Instagram DM і Messenger з’являються лише для опублікованих бізнесом посилань, текст копіюється автоматично.
- Карта OpenStreetMap (Leaflet) без ключа: кольори за оцінкою, підказки, коло зони пошуку, легенда.
- AI: OpenAI-сумісні провайдери через `AI_BASE_URL` (Gemini, OpenRouter, Groq, Mistral, DeepSeek, локальний Ollama), типова модель Anthropic `claude-opus-5`, обробка відмови моделі, кнопка «Перевірити AI».
- Перетягування лідів між етапами кампанії.

### Перевірка

`npm run lint`, `npm run typecheck`, `npm test` (97 тестів), `npm run build`, `npm audit --omit=dev` — без помилок. У браузері (Chromium, 1440 px і 390 px) пройдено демо-сценарій: пошук → картки/таблиця/карта → деталі з контактами → збереження → перетягування на дошці → налаштування; помилок JavaScript немає. Реальні ключі Google/AI не перевірялися: їх немає в архіві.

## Висновок

Проєкт доопрацьовано як локальний інструмент для агенції або фрилансера. Пошук, відбір, кампанії, шаблони звернень і перенесення даних утворюють завершений робочий сценарій. Реальні Google та AI інтеграції реалізовано в коді; їхня робота з конкретним обліковим записом потребує ключів власника й окремої перевірки. Публічного розгортання не виконано.

## Виправлені проблеми

- Google-помилки та порожні відповіді більше не маскуються демо-лідами.
- Запити проходять перевірку типів, діапазонів і розміру; помилки користувача повертаються як 4xx.
- Виправлено розпізнавання міст, коротких слів, районів та кількості лідів; «медичний центр» не стає адресою в центрі Києва.
- Радіус не пропускає далекі результати, навіть коли всередині кола нічого не знайдено; для фільтрації не використовується округлена відстань.
- Додано реальну пагінацію Places, бюджет запитів та пріоритет міжнародного номера телефону.
- Зміна запиту скидає старі фільтри; запізніла відповідь попереднього пошуку не перезаписує нову.
- Виправлено запити за reverse proxy: порівнюється також фактичний публічний origin.
- Помилки localStorage не видаються за успішне збереження; пошкоджений JSON не стирається автоматично.
- CSV захищено від виконання формул; JSON-імпорт перевіряє структуру, унікальність і розмір.
- «Не контактувати» реально блокує кнопки звернень. Демо-контакти не використовуються для зовнішнього зв’язку.
- SSRF-перевірки охоплюють IPv6, DNS, redirect і DNS rebinding; завантаження HTML обмежене за розміром і часом.
- Оцінки та шаблони не стверджують без доказів, що бізнес втрачає клієнтів, має поганий дизайн або отримає гарантований результат.
- Оновлено залежності, додано захисні HTTP-заголовки, optional password gate і CI.
- Виправлено збереження дати при втраті фокуса, горизонтальне переповнення мобільних карток і позиціонування діалогу після прокручування.

## Функціонал і вигляд

Новий огляд із реальними показниками кампаній, темна бічна навігація, світла робоча зона, зелений акцент, акуратні картки й адаптивна нижня навігація. Додано таблицю результатів, масове збереження, виділення, пошук у завантажених лідах і повернення прихованих записів.

Кампанії отримали п’ять етапів, пошук, наступний крок, ручні перевірки, нотатки, дату контакту й редагування підсумку. Додано JSON-копії з об’єднанням, попереднім переглядом і підтвердженням повної заміни. Чернетки зберігають ручні зміни під час перемикання мови й каналу в межах відкритого робочого сеансу.

Підключено optional OpenAI Responses / Anthropic Messages для редагування чернеток, перевірку доступності Google і стан конфігурації без розкриття секретів. Діалоги підтримують Escape, утримання фокуса й повернення фокуса після закриття.

## Практичні межі

1. В архіві немає ваших API-ключів. Не перевірені реальний білінг, квоти, доступ до моделі, реальна карта й запити конкретного Google/AI-акаунта.
2. Кампанії локальні: немає БД, користувачів, хмарної синхронізації чи підключення CRM.
3. HTML-аналіз не виконує JavaScript і не вимірює швидкодію. Скоринг є евристикою; кількість лідів залежить від джерела та фільтрів.
4. Відомі райони Києва мають вбудовані координати. Для інших адрес без координат не обіцяється точний радіус.
5. Частотні ліміти діють на один процес. Публічний багатокористувацький сервіс потребує окремих облікових записів, квот і спільного сховища.
6. Експорт і локальне збереження Google-контенту треба узгодити з [умовами Places](https://developers.google.com/maps/documentation/places/web-service/policies). Повного правового аудиту або сертифікації відповідності не виконано.
