# Реальный пилот: отбор заказов для владельца

28.09.2026 · Текущий приоритет после разбора 0.6.0

Цель: выяснить, экономит ли приложение время и повышает ли качество отбора по сравнению с обычным ChatGPT. До измерения не добавляем новые разделы, поисковые интеграции, платежи или механизм автономной компании.

## Первый запуск: конкретные действия

1. Остановить старую программу, сохранить копию её SQLite-базы. Распаковать 0.6.1 в отдельную папку.
2. Windows: дважды нажать `CHECK-WINDOWS.cmd`. Mac: открыть `CHECK-MAC.command`. Передать полученный диагностический JSON в текущий чат. Если запуск Mac двойным щелчком не работает, в Terminal из папки выполнить `bash CHECK-MAC.command`.
3. Запустить `START-WINDOWS.cmd` или `START-MAC.command`. В браузере открыть «Инструменты» → «Проверить подключения».
4. Выбрать исполнителя. Для самого первого сквозного теста допустим ручной ChatGPT. Для Ollama явно указать установленную модель, подходящую объёму памяти, вместо доверия выбору наименьшей. Для Claude нужен реальный совместимый официальный CLI; в Windows этот адаптер пока отключён.
5. Взять один реальный свежий заказ, открыть первоисточник, проверить бюджет, статус и обязательные требования. Создать задачу и импортировать материал по шаблону. Время поиска и подготовки материала тоже засекать.
6. Сначала выбрать одного аналитика. При ручном ChatGPT нажать «Скопировать запрос», вставить в чат, получить полный JSON, вставить его в карточку роли и нажать «Принять ответ». При отказе буфера использовать скачивание.
7. Проверить вывод: действительно ли он следует из источника; не перепутан ли бюджет; указаны ли неизвестные условия; понятен ли следующий шаг. Не считать совпадение цитаты смысловым доказательством.
8. Записать результат и всё затраченное время. После удачного одиночного прогона отдельно проверить бригаду и выяснить, оправдывает ли дополнительный вызов себя.

Историческое демо помогает посмотреть формат. Оно не входит в выборку реальных заданий и не доказывает актуальность заказов.

## Десять задач: как сравнивать

Заранее выбрать 10 реальных разных задач отбора, у каждой 1–3 объявления. Сохранить исходные страницы/текст, время проверки и одинаковый профиль. Не отбирать только простые примеры. Включить отсутствующий бюджет, непонятный допуск, истёкший срок и неоднозначные требования.

Сравнить два способа: А — обычный ChatGPT, Б — приложение с выбранным исполнителем. Начинать с А на нечётных задачах, с Б на чётных. При повторном знакомстве с материалом учитывать возможный эффект запоминания; это небольшой личный пилот, не строгий научный эксперимент. Не смешивать результаты разных моделей без отметки.

Для каждого способа учитывать активные минуты: сбор источников, подготовка/импорт, взаимодействие, ручная проверка и исправления. Отдельно записывать ожидание модели, её имя, ошибки инфраструктуры, число попыток и фактические/неизвестные расходы. Таймаут отмечать как инфраструктурный сбой; он всё равно входит в пользовательское время и возможные расходы, но не выдаётся за смысловую ошибку ответа.

Таблица `real-pilot-template.csv` находится в папке `reports/`. Пустые поля означают «не измерено». Не заполнять их фиктивными нулями.

Критерии качества: корректный бюджет; верный статус/срок; соответствие навыкам с оговорёнными неизвестными; утверждения следуют из источника; следующий шаг применим. Критической считать ошибку, из-за которой человек принимает неверное решение об отклике. До измерения записать эти правила и не менять их ради удачного результата.

## Решение после десяти задач

Продолжать при отсутствии критических ошибок, качестве не хуже базового способа и снижении медианы активного времени хотя бы на 20%. Это стартовое правило решения, не доказанный результат и не статистическая гарантия. Если времени больше — определить конкретный самый дорогой шаг. Если выигрыш отсутствует, упрощать процесс или оставить обычный ChatGPT.

Не проводить сейчас 60 оценок для применения новой инструкции. Пробный режим раздела «Улучшения» можно использовать для знакомства; он не даёт права на применение. Отдельный облегчённый протокол, инфраструктурные повторы и новая модель затрат вводятся лишь после данных первого пилота.

## Следующие две недели реального использования

Самостоятельно выбирать и отправлять подходящие отклики через свои аккаунты. Записывать число рассмотренных заказов, отправленных откликов, ответов, выигранных заказов и часы работы. Приложение не отправляет их автоматически. Сравнить с прежним способом; изменения рынка и состава заказов учитывать как возможное объяснение различий.

Критерий следующей разработки: конкретный шаг съедает большую часть времени и его автоматизация сохраняет качество. Кандидаты — импорт источников, исправление транспортных сбоев, связанный учёт запусков. Приоритет определяют измерения.

## Отдельная гипотеза продажи отчётов

Это другая услуга, не реализованная функция текущего приложения. Если владелец решит проверить её, сначала вручную предложить понятный результат 20–30 подходящим людям по согласованным каналам. Рабочий ориентир — три реальных обезличенных примера и две оплаты/предоплаты на заранее согласованных условиях. Интерес и похвала не заменяют оплату. Только после этого автоматизировать наиболее трудоёмкий шаг. Сейчас таких обращений и оплат не было.
